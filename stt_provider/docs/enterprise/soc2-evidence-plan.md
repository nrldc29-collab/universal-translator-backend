# Phase 3 Step 7: SOC 2 Type II Evidence Collection

## Target

Begin SOC 2 Type II evidence collection now so enterprise-readiness work is tracked continuously instead of being reconstructed later.

## Approved evidence platforms

Use one of:

- Vanta
- Drata
- Secureframe

Default choice:

- Vanta

## Systems to connect

Connect the evidence platform to:

- Cloud provider account
- Kubernetes cluster
- GitHub repository
- Ticketing system
- HRIS, if available
- Identity provider
- Device-management system, if available
- Incident-management system
- On-call system
- Status page provider

## Evidence categories

Track evidence for:

- Access control
- Change management
- Incident response
- Vendor management
- Risk assessment
- Security monitoring
- Data retention
- Backup and recovery
- Business continuity
- Encryption
- Vulnerability management
- Employee onboarding and offboarding

## Required recurring evidence

Collect or verify monthly:

- User access review
- Admin access review
- Production deploy history
- Security incident log
- Vulnerability scan results
- Backup status
- Cloud security findings
- Policy acknowledgements
- Vendor review status

## Initial policies to create

Create these policy documents before the first readiness review:

- Information Security Policy
- Access Control Policy
- Change Management Policy
- Incident Response Policy
- Vendor Management Policy
- Risk Assessment Policy
- Data Retention Policy
- Backup and Recovery Policy
- Business Continuity Policy

## Acceptance checks

- Evidence platform is selected.
- Core systems are connected.
- Monthly evidence tasks are assigned.
- Initial security policies exist.
- Access reviews are scheduled.
- Incident-response workflow is documented.
- SOC 2 readiness owner is assigned.

This implements Phase 3, Step 7: start SOC 2 Type II evidence collection early using a platform such as Vanta, Drata, or Secureframe, and connect cloud, code repo, ticketing, and HR systems as evidence sources.
